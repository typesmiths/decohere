# 0007. A module serves its built UI from its API: `withStatic`, outside the pipeline, cached by file kind

- **Status:** Proposed
- **Date:** 2026-10-12 · updated 2026-10-21

## Context

A module deploys itself: one image runs its API and serves its UI's build, so the two always ship as a matching pair and the UI calls the API on its own origin (no CORS, no second service). Ledger's `crypto` module needs this (`crypto.api` serving `crypto.web` at `/ui/`). The HTTP package could not serve files, and the only options were a hand-written file controller or a second service in front. Fastify details stay in the provider ([architecture](../architecture/#provider-boundaries--manage-vendor-lock-in)). Building the UI with its own toolchain (`vite build`) is not decided here.

## Decision

- **API.** `builder.withStatic(prefix, directory, options?)`, for example `.withStatic("/ui/", "ui")`. The prefix is normalised to `/ui/`; `/` mounts the UI at the root (see SPA fallback); an empty prefix, and mounting one prefix twice, are refused. The directory is resolved from the process working directory when the app starts, like `./config`; the global prefix does not apply. The call can be repeated for several UIs. The options type (`StaticOptions`), the caching rules and the missing-directory policy are provider-neutral and live in `src/http/http.static.ts`. Only the registration of `@fastify/static` is in `FastifyProvider`.
- **Outside the pipeline.** Static files are Fastify routes beside the HTTP routes, not entries in the route registry. They run before and without the Router, so `@Authorize`, token checks, request validation and middleware never apply to the prefix: a UI shell is public. A side effect is that middleware such as the access log does not see them, and that the routes are absent from OpenAPI (they are not in the registry the document is generated from). Helmet and CORS are Fastify plugins and still apply.
- **Rate limit: exempt.** The static prefix is outside the global rate limit. A single page load fetches dozens of files, so the API default (100 per minute) would answer 429 to ordinary use, and the limit exists to protect handlers that do work, which a file read does not. The exemption is an `allowList` entry added to the rate-limit plugin that matches the route the request resolved to (`/ui/*`), not the URL text, so it cannot be reached by a crafted path; a caller's own `allowList` keeps working. A separate generous limit was rejected as another number to tune that protects nothing here. Bandwidth abuse is for the CDN or proxy in front.
- **Caching, by kind of file.** `Cache-Control` is set per file:
  1. a name on the `noCache` list, matched by file name or relative path: `no-cache`. Default `index.html` and `remoteEntry.js`: `index.html` names the hashed bundles, and a module-federation host loads the remote entry by a fixed name, so neither may be cached;
  2. a name carrying a content hash (8 or more letters, digits or `_` after a `-` or `.`, with a digit or a lower-then-upper letter pair, before the extension; `.map` allowed after it): `public, max-age=31536000, immutable`;
  3. everything else: `public, max-age=0, must-revalidate`, with `ETag` and `Last-Modified`, so the browser asks again and gets a 304.
  The hash rule is deliberately narrow: a file wrongly marked immutable is stuck in browsers for a year, a file wrongly revalidated costs one 304. Plain words (`logo-background.png`) do not match. `noCache`, `immutable` (a pattern, or `false`) and `cacheControl` (the default for the rest) replace the rules.
- **SPA fallback.** An unknown path under the prefix serves `index.html` (default on, `spaFallback: false` to opt out) only for a browser navigation: GET or HEAD, no file extension and no dotfile in the path (a missing asset is a real 404), an `Accept` header that includes `text/html` (`text/html;q=0` does not), and a path that is not under one of the app's own routes. Anything else, such as a JSON request, `*/*`, or POST, gets the normal JSON 404 of the HTTP package, with the body and headers it has without a UI. The rule is the same under every prefix. It is the not-found handler of an encapsulated Fastify context registered at the prefix; at `/` that handler is the app's own not-found handler, which is why it must hand back everything it does not take. `/ui` redirects (301) to `/ui/`, also when a root mount exists (the root handler redirects for the other mounts).
- **Root mount.** `withStatic("/", "ui")` works with no config. Fastify already matches a specific route before the static wildcard, so API routes, `/health` and OpenAPI are never shadowed; the open question was what an unknown path returns. Two automatic rules answer it: the `Accept` rule above (an API client mistyping `/lp/portfolo` asks for JSON and gets the JSON 404, not HTML with status 200) and "under the API": without a global prefix, a path whose first segment is the first segment of any HTTP route (controllers, `/health`, the OpenAPI path) is never answered with the app, even for a browser; with a global prefix, the API is the prefix itself plus the OpenAPI path, so a path under `/api` (or the OpenAPI path) is never answered with the app and every other name is free for the UI. The first-segment rule is a guess made because nothing says where the API lives, so it is kept only for that case. First segment, not an exact or longer-prefix match, because a mistyped path under `/lp/portfolio` is exactly what must stay an API 404 and the route table has no controller prefix to compare against; the cost is that, without a global prefix, a client route sharing a first segment with an API route (`/portfolio` next to `/portfolio/items`) is not served the app, so such a client route needs a different path, or the app sets a global prefix. Routes the prefix leaves out, those of a controller declared with `globalPrefix: false` (the health probes), are part of that boundary too: the literal start of each (up to its first parameter) and every path below it. Parameter first segments (`/:id`) are ignored. `exclude: string[]` lists globs (picomatch, already a dependency of the repo; `*` within a segment, `**` across segments) that the mount never answers at all, matched on the decoded full path. A routing table or middleware were rejected: static stays outside the pipeline, and two rules plus a list cover the case. The rate-limit exemption is still keyed on the route the request resolved to (`/*` at the root), so API routes, which resolve to their own route, are not exempt. With two mounts the more specific prefix wins.
- **Security.** Traversal protection, `dotfiles: "ignore"` (404), no directory listing, HEAD and conditional requests come from `@fastify/static` and are tested with raw requests (`..`, encoded, double-encoded, backslash, NUL), not assumed.
- **Missing directory.** `onMissingDirectory`: `"fail"` stops the app at start with an error naming the path; `"warn"` logs a warning and serves nothing, so the API still boots before the UI is built. The default is `"warn"` when `NODE_ENV` is `development` or `dev` (the same test auth uses for `devStatic`) and `"fail"` otherwise, so a production image without its UI does not start as a healthy API with a dead front end.
- **`forge package`.** A deployable declares its UI in `.decohere.js`, beside `docker`: `projects["@app/shop.api"].ui = { project: "@app/shop.web", output?: "dist", to?: "ui" }`. Packaging copies `<ui project>/<output>` to `.package/<to>/` (files, never links) and fails with "build the UI first" when the folder is missing. It does not build the UI. The API's Dockerfile does not change (`COPY .package/ ./`), and `withStatic("/ui/", "ui")` finds the folder because the container's working directory is `.package/`.
- **Dependency.** `@fastify/static` (MIT, maintained by the Fastify team, no known advisories when added) rather than a hand-written file server, for path-safety, ranges, conditional requests and content types.

## Consequences

- The UI shell and its assets are public. Anything private must come from the API, behind `@Authorize`.
- Static requests are not access-logged by the HTTP package's middleware. A proxy or CDN in front logs them.
- The file list is read from disk on each request (`wildcard: true`), so a rebuilt UI is served without a restart in development; a directory that did not exist at start is not picked up until restart.
- Pre-compression (`.br`, `.gz` files), a Content-Security-Policy tuned to the UI, and a per-mount rate limit are not done. Files are compressed on the fly like any response ([ADR 0008](0008-response-compression-in-http.md)); serving pre-compressed files is not done yet.
- Forge does not run the UI's own build: `forge package` needs the UI built first. Making `forge build` run `vite build` and package in one step is not done yet.
- Only one UI project per deployable can be declared (`ui` is a single object). Serving several from one API is possible with `withStatic`, but not yet declarable for packaging.
- A route registered by a controller under the same prefix as a non-root mount is shadowed or conflicts; keep the prefix to the UI. A root mount does not shadow routes, but, with no global prefix, a client-side route that shares its first segment with an API route is answered with the JSON 404. With a global prefix only paths under it are.
- The app is served only to requests that say they accept HTML. A client that sends no `Accept` header (a bare `curl`) gets the JSON 404 for client routes; `GET /` and files do not depend on it.

## History

- 2026-10-12: Decided.
- 2026-10-12: A root mount is allowed; the fallback decides by `Accept`, by registered routes and by `exclude`.
- 2026-10-12: With a global prefix the fallback's API boundary is the prefix and the OpenAPI path, not the first segment of every route; without one the first-segment rule is unchanged. The prefix leaves `/health` and `/ready` at the root by default and takes an `exclude` list.
- 2026-10-14: The `exclude` list is gone before release: a path list had to be kept in step with the controllers and matched any controller that declared the same path. A controller opts out of the prefix instead (`@Controller({ globalPrefix: false })`), the health controller does, `withHealth({ underGlobalPrefix: true })` puts it back, and routes outside the prefix count as the API for the fallback.
- 2026-10-21: Package names updated to the plain names of [ADR 0014](0014-package-names.md). The decision is unchanged.
